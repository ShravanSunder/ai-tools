# 2026-09-08: Review handoff audit — what reaches a fresh reviewer, and where the rails leaked

Plugin: `shravan-dev-workflow` 2.10.0 (combined release)

Two independent Claude Fable auditors walked `implementation-review` and `spec-program-review` as a coordinator would run them, against the owner's two real-world failures: reviewers judging from partial information, and scope expansion surviving review. Both returned "yes, with fixes." Fixes applied:

- **Reviewer packets are now self-sufficient.** `lane instructions` carries absolute paths (or inlined text) for every reference a reviewer is told to load — a fresh subagent in the reviewed repo cannot resolve the skill's relative paths. Goal boundary and accepted requirements travel as quoted statements with authority sources; chat-only owner records are copied verbatim into the tmp packet (the old `spec-program-review` §3 prohibition applied to durable artifacts, not packets). Constraints carry the authority that imposed them; a constraint stated only inside the reviewed artifact is a claim to audit, not a rail. `implementation-review` materializes the diff to a file so reviewers get content, not a range; chunk file sets include every current consumer of a changed contract, changed or not.
- **Two kinds of scope expansion, two dispositions.** A reviewer candidate that *adds* unanchored scope is `rejected: scope expansion` and listed as an observation — never `decision-needed`, so a gold-plating reviewer cannot steer the verdict. A delivered element the change already contains that dispel maps `absent` is never "non-defective": removal or `decision-needed`. New `mechanism necessity` anchor field stops anchoring a mechanism one altitude up; accepted findings name the unrealized obligation, never the reviewer's mechanism. Parent overrides of dispel must quote the rail. Deletion test unified to "do the confirmed obligations still hold without the mechanism?"
- **`manage-agents`**: self-fork/resume-self named as forbidden for reviewers on every host; reviewer packets must carry everything they cite; new access class `read-only + exec <listed commands> (declared)` for proof verification with post-run `git status --porcelain` verification, so the proof-challenge grant has an encoding instead of forcing an over-grant.
- **Proof-challenge** write-set classes now `scratchpad-only | ignored-build-artifacts | tracked-worktree | unknown`, so gitignored coverage/cache output no longer stops every command; a lane that could execute nothing cannot be the sole proof for a changed contract. Spec-compliance `misread requirement` skips fan-out and returns to the semantic owner. Admission without any plan record has an explicit legal path (`diff-only-limited` or `risk-triggered` with the user's goal statement as sole rail) instead of inviting plan inference.
- Validation: lib suite (121), typecheck, `claude plugin validate .`; dispel scenarios re-run under the corrected dispositions.
