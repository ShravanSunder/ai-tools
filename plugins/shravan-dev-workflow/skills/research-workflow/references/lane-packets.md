# Source-Class Checklists

The researcher walks selected classes one at a time. Each class returns opened anchors, verbatim queries, null results, contradictions, freshness, and what remains unsearched. Select by the question and preserve named targets. These checks produce candidate evidence; the researcher verifies load-bearing conclusions before synthesis.

| Source class | Use when | Inspect and return | Fallback |
| --- | --- | --- | --- |
| Local code and docs | A local implementation or contract constrains the answer | Current branch and file tree, owner modules, callers, specs, plans, runbooks, findings, sibling prior art; exact anchors | State inaccessible paths and the resulting gap |
| Repository architecture | An open-source repository API or structure matters | DeepWiki pointers, then primary repository files or official docs for the claim | Search official repo/docs directly and name the route gap |
| Current web and docs | Version, policy, release, or platform facts may have changed | Current sources and dates, primary URLs, conflicting claims | State unavailable tool and use accessible primary source |
| Specific URL or document | The user named an article, issue, PDF, or page | Open that exact target first; cite its supported claims and limits | Report access failure before generic search |
| Saved research | The user's Reader material is relevant | Saved item identity, date, source, and whether it still applies | Name unavailable saved-source access |
| Memory and sessions | Prior decisions or repeated patterns matter | Targeted memory summary, then source session only where needed; mark memory-derived claims | Report missing history and do not infer current state |
| UI or browser behavior | A page or app's actual behavior matters | Observe the real surface and record state, action, and outcome | Report inability to observe; source alone does not prove runtime behavior |
| Coverage map | Every substantial run | Searched classes and queries, null results, not-searched reasons, contradictions and gaps | Preserve the gap explicitly |

For local re-anchor, read current implementation and its controlling artifacts before external comparison. For prior art, compare one target or axis at a time and return what fits or conflicts with the local system. For memory, treat older summaries as discovery until live evidence confirms drift-prone facts. For artifact consistency, read current specs, plans, runbooks, changelogs, and findings together; read newest-first runbooks in their established order.

Substantial research writes one ledger under `tmp/research-workflows/<date>-<slug>/`. A chat-only, no-file, tiny single local read, or unavailable write surface names its exception. The ledger belongs to this researcher; source classes do not create separate packet or result files by default.
